# 첫 배포 호환 규칙과 과거 증거 보존

[영문 정본](COMPATIBILITY.md). 기본 지원 형상은 같은 릴리스의 이슈어·게이트웨이·게이트·SDK·도구·예제 설정을 함께 쓰는 것이다. 모든 구버전과의 자동 협상·혼용 지원을 뜻하지 않는다.

## 실행 전 묶음 확인

[RELEASE.md](../RELEASE.md)에 안내된 scripts/verify_release.py 명령에 의도한
--expected-release와 신뢰한 manifest를 주어 식별자·파일/아카이브 해시·묶음 경계를 확인한다.
누락이나 불일치는 성공이 아니다. 이 검사는 받은 파일을 확인하며 임의로 이미 실행 중인
프로세스의 출처까지 확인하지 않는다. 예제의 이미지 digest·빌드 근거를 유지하고 이름만 같은
실행 파일로 바꾸어 검증된 조합이라고 하지 않는다.
검증기는 지원 호스트에서 설치된 암호 라이브러리를 요구하지 않는다: Core 소스가
`cloud/cmd/pail_verify`(표준 라이브러리만; `verify_release.py` 가 `go run` 으로 쓴다)를 싣고,
모든 평가 꾸러미가 그것을 `native/pail_verify-<host>` 로 빌드해 동봉하며 사용 전에 lock 과
대조한다. 검증 PASS 는 꾸러미 밖에 영수증을 남기고, 평가 launcher 의 `load` 와 실행 동작은
그것을 읽어 `VERIFICATION:` 줄을 찍고 `platform.json` 에 기록한다 — 기본은 보고이고
`--require-verified` 일 때만 거부한다.

| 계약 | 정책 |
|---|---|
| 게이트 ABI·서명 토큰 스키마 | 기존 검사 유지. 새 토큰 필드를 추가하거나 미지원 필수 권한 검사를 완화하지 않음 |
| TOKEN_ISSUED·GATE_DECISION v10 | [완료 저널 계약](COMPLETION_JOURNAL.ko.md)의 reader·restorer 필요 |
| 미래 발급·완료 의미 버전 | 새 운영 reader가 거부하며 추측하지 않음 |
| 완료 규칙 없는 구형 skill 발급 | LEGACY_COMPLETION_AMBIGUOUS로 운영 복원 거부. 무결성 검증용 원래 바이트 읽기는 유지 |
| skill 이전의 식별 가능한 기록 | 기존 고정 레거시 해석 유지. 모든 과거 skill 설정을 지원한다는 뜻은 아님 |
| 과거 완료 보고의 관측 표시 | 수용 여부 미상. 확인된 완료로 표시하지 않음 |
| 새 저널을 구형 런타임·도구에 연결 | 미지원. 구형 실행본은 새 필드를 무시할 수 있으며 문서로 그 검사를 바꿀 수 없음 |
| 임의 버전 혼용 | 첫 공식 지원 경로 아님. 별도로 시험한 조합이 아니면 호환 확인 불가 |

## 증거 보존과 운영 재개는 별개

원래 토큰·세그먼트·신뢰 기점·검증 입력을 보존한다. 무결성이 정상인 과거 저널도
활성 권한을 복원하는 데 필요한 수용·완료 근거가 부족할 수 있다. 서명된 원장을 다시 쓰거나
수용 필드를 만들어 넣거나 재생 검사를 우회해서 시작하지 않는다.

기본 이전은 기존 로봇 권한·실행을 정리하고 증거를 보존한 뒤 새 평가 상태와 계획으로 시작하는
계획된 전환이다. 로봇이 동작 중인 상태를 지우지 않는다. 범용 원위치 마이그레이션이나 롤링
다운그레이드는 이번 변경에 포함하지 않는다. 복원이 불가능한 경우에는 이전 절차를 별도로 정한다.

## 후속 버전

JSON 모양뿐 아니라 외부 의미를 버전 관리한다. 선택 메타데이터와 필수 인가 조건을 구분하고
지원 조합·변경 의미·이전 절차를 출시 안내에 적는다. 이 계약을 지키는 한 내부 구현은 바꿀 수 있다.

이 계열에서 바뀐 외부 계약(추가만; `spec/vectors/contract/ros_msgs.vec` 에 선언):

- `pail_msgs/GateState` 는 `effective_mode` 뒤에 네 필드를 더 싣는다: `detail`(거부 상세),
  `step_deadline_elapsed_ms`(활성 스텝의 기한, 게이트 경과 시계 기준), `step_clock_id`(그 시계의
  식별자), `completed_token_id`(완료 PERMIT 이 소비한 토큰). 앞 일곱 필드를 이름으로 읽는 구독자는
  영향이 없고, 필드 수로 메시지를 고정한 구독자는 열한 개로 바꾼다.
- 사유 등록부: `ERR_BUNDLE_CLOCK`·`ERR_BUNDLE_LIFETIME`·`ERR_BUNDLE_POLICY`(키링 번들 로더의
  기동 거부, 로컬 평면, 선상 미발행)를 0x8B–0x8D 로 등재했다. 이 후보 전에는 게이트가 등재 없이
  발행하고 있었다.

## 상태 복원 이슈어 진입점

이 문서의 운영 재생 검사는 replay가 켜진 pail_cloud 경로에 연결된다. 기존 통합형
pail_services 진입점은 이 복원 경로를 호출하지 않으므로 기존 권한 저장소를 이어가는
대체 실행 경로로 지원하지 않는다. 매번 새 상태로 시작하는 레거시 데모와는 범위가 다르다.
모호한 원장 거부를 피하려고 replay를 끄지 않는다.
