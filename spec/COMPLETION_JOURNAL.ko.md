# 완료 저널 계약 — 의미 버전 10

[영문 정본](COMPLETION_JOURNAL.md). 완료의 해석이 바뀌므로 새 JSON 필드를 무시하는 구형
도구는 운영 호환 도구가 아니다. 세그먼트 바이트 형식과 서명 토큰 형식은 바꾸지 않았다.
배포 경계는 [호환 규칙](COMPATIBILITY.ko.md)을 따른다.

## 보고·수용·소비 구분

기존 decision·step_complete·detail은 게이트의 원래 보고다. 거부된 완료를 숨기려고
보고 필드를 바꾸지 않는다. GATE_DECISION journal v10에는 이슈어 결과가 추가된다.

| 필드 | 의미 |
|---|---|
| completion_result | not_requested / rejected / accepted |
| completion_reason | 게이트 reason_code와 구분되는 이슈어 수용 결과 사유 |
| consumed_sequence_index | accepted일 때만 필수. 실제 소비한 토큰 순번 |
| next_expected_index | accepted일 때만 필수. 소비 순번 + 1 |
| lease_reported_at_after | accepted일 때만 필수. 위임 없으면 0, 있으면 소비 순번 |

수용 기록은 귀속된 비치명 PERMIT 완료여야 한다. 필수 필드 부재·모순·미지원 의미 버전은
거부한다. 과거 기록의 결과 부재는 수용이 아니라 미상이다.
이슈어는 토큰·체인·위임 범위와 완료 규칙을 먼저 확인한 뒤 수용 기록을 쓴다.
잘못된 신호는 rejected 보고로 남기고 소비 순번을 붙이지 않는다.

## 상태 효과의 정본은 한 기록

수용된 GATE_DECISION 한 건이 위임 소비 위치까지 포함한다. 같은 v10 완료에 별도
LEASE_RECONCILED OK를 추가 필수 기록으로 요구하거나 쓰지 않는다. 과거 위임 기록과
OVER_LEASE 철회 읽기는 유지한다.

수용 완료에는 성공 응답 전 명시적인 로컬 fsync를 수행하며 기존 동기 복제 경로도 유지한다.
다른 보고의 배치·flush 정책을 모두 바꾼다는 뜻은 아니다.

기록 함수가 오류를 반환해도 이미 일부 바이트가 기록·복제됐을 수 있다. 이 경우 이슈어는
기존 기록 실패 보호 상태로 전환하고 RPC를 사용 불가/결과 불확정 오류로 응답한다.
‘분명히 소비되지 않았다’고 말하지 않으며 재조정 없이 재시도를 단정하지 않는다.
정상 기록 후 응답 전 중단은 복원 상태가 중단 전 메모리보다 앞설 수 있다.
반면 잘못된 완료 신호에 대한 의미상 거부는 단계를 소비하지 않는다.

TOKEN_ISSUED v10은 발급 당시 completion_signal도 기록한다. 빈 값은 명시적인
레거시/no-skill 경로에서만 허용한다. 재생은 오늘 바뀐 skill 설정으로 과거 계획을
다시 해석하지 않고 기록된 규칙을 복원한다.

## 읽기·화면

운영 재생은 토큰과 순번의 결속·권한 범위·정확한 다음 위치를 확인하며 같은 상태 효과를
다시 읽었다고 위치를 더하지 않는다. 계획 완료와 결정 이력은 보고·수용·거부·미상을 구분한다.
완료 수용은 프로토콜 결과이지 실물 성공·제동 성능·센서 진실의 증명이 아니다.
UIR의 확인된 완료 분모에도 이슈어 수용만 포함하며 과거 보고를 임의로 완료에 더하지 않는다.
