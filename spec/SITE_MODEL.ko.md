# 사이트 모델 (`PAIL_SITE_MODEL`)
<!-- ko-structure: abridged -->

> 이 한국어판은 영문판보다 절·표·코드 블록이 적은 요약본이다. 영문판이 정본이며, 두 판이 다르면 영문판이 우선한다.

사이트 모델은 운영자가 자기 현장을 PAIL 이슈어에게 기술하는 **파일 한 벌**이다.
구역·물체·로봇, 그리고 그 위에 성립하는 규칙을 적는다. 이슈어는 기동 시 이것을
컴파일해 자기가 인가 판단에 쓰는 컨텍스트 그래프로 삼고, 발급하는 모든 토큰에
그 그래프의 관련 조각의 해시를 묶어 넣는다.

> 정본은 영문 [`SITE_MODEL.md`](SITE_MODEL.md). 두 판이 갈리면 영문이 지배한다.

## 1. 왜 코드가 아니라 파일인가

세계 모델은 **이슈어를 쓰지 않은 사람**이 받아들여야 한다. 현장을 기술하는 데
코드 수정이 필요하다면 현장마다 사설 포크가 생기고, 포크가 가장 먼저 고치는 곳은
**거부하는 부분**이다.

그래서 사이트 모델은 선언적이고, 그것을 읽는 것은 컴파일러뿐이다. 증거 계약은
YAML 에 있지 않고 그래프 모델과 그 정규 인코더에 있다 — 같은 논리적 현장은 키를
적은 순서와 무관하게 같은 스냅숏 해시를 내고, 다른 전단(JSON, API)이 바이트가
같은 그래프를 만들 수 있다.

## 2. 적재, 그리고 적재가 실패할 때

`PAIL_SITE_MODEL` 이 경로를 담는다. 값이 없으면 사이트 모델을 적재하지 않고
요청마다 만드는 임시 그래프로 돌아간다 — 사이트 모델 이전의 거동이다.

값이 있는데 파일을 읽지 못하거나 컴파일하지 못하면 이슈어는 **기동하고 모든
발급을 거부한다.** 임시 그래프로 되돌아가지 않는다. 세계를 선언했는데 오타가 난
현장을 **아무것도 선언하지 않은 현장처럼** 다루면, 그 폴백은 실패보다 조용하고
실패보다 명백히 덜 안전하다.

파싱도 같은 정신으로 엄격하다. 모르는 키는 무시되지 않고, 오타 난 제약 type 은
건너뛰어지지 않으며, 선언된 적 없는 구역에 대한 참조는 「없음」으로 해소되지
않는다. 각각이 컴파일을 중단시킨다. 막으려는 실패는 구체적이다 — **썼다고 믿는
규칙이, 실은 존재하지 않고, 아무도 그것을 알려주지 않는 상태.**

### 2.1 서빙 모델의 스냅샷

발급자는 `PAIL_SITE_MODEL`을 적재할 때 그 정확한 바이트를 SHA-256 이름으로 —
`PAIL_SNAPSHOT_DIR/<hash>.yaml`(기본 `/var/log/pail_blackbox/snapshots`) — 모델이 서빙되기
전에 보관하고, 보관할 수 없으면 기동을 거부한다(`S23`). 모든 `TOKEN_ISSUED` 레코드가 그
해시(`site_model_hash_hex`)를 적으므로, 과거 허가에 대한 질문은 오늘의 모델이 아니라
그날의 모델로 답한다. 이름이 곧 내용이다: 바이트가 자기 이름으로 해시되지 않는 파일은
스냅샷이 아니다.

| 책임 | 누가 | 어떻게 |
|---|---|---|
| 생성 | 발급자, 사이트 모델 적재 때 | 내용 주소 쓰기(임시 파일, fsync, rename); 디렉터리를 쓸 수 없으면 `S23` |
| 보존 | 운영자 | 저널과 같은 디렉터리 계열·보존 기간(`spec/DURABLE_STORES.tsv`); PAIL의 어떤 것도 스냅샷을 지우지 않는다; 지워진 스냅샷을 가리키는 행은 `unresolved`가 되며 추측하지 않는다 |
| 무결성 | 저장할 때 발급자, 읽을 때 수집기 | 같은 이름 아래 다른 바이트가 이미 있으면 발급자는 기동을 거부한다(`S23`, 덮어쓰지 않음); 수집기(`pail_telemetryd`)는 읽은 스냅샷을 다시 해시해 불일치를 「해석 불가」로 다룬다 |
| 조회 | 원장 조회 | 모든 행의 `site_model_hash`; `zone_resolution`은 `recorded`, `snapshot`(내용을 이름과 대조함), `unresolved`, `none` |
| 독립 검증 | PAIL 코드 없이 누구나 | `sha256sum <hash>.yaml`이 파일 자신의 이름을 찍어야 한다; 스냅샷은 공개 사이트 모델 컴파일러로 컴파일된다 |
| 회귀 자료 | 릴리스 시험 | 수집기는 내용이 이름과 다른 스냅샷을 거부한다; 발급자 저장소는 한 이름 아래 다른 바이트를 거부한다 |

스냅샷은 이동이 성공했는지, 센서가 진실을 말했는지, 키가 만료됐는지를 말해 주지 않는다.
그것은 허가가 판정된 선언이지 실행의 기록이 아니다.

## 3. 최상위 키

<!-- vocab: top -->

| 키 | 필수성 | 뜻 |
| --- | --- | --- |
| `site` | required | 현장 식별자. 기록된다. 없으면 컴파일이 실패한다. |
| `schema` | optional | 운영자가 선언하는 이 현장의 토큰 스키마 판. **기록만 된다** — 기동 로그에 찍힐 뿐 어떤 발급 경로도 읽지 않는다. 여기 적은 값은 발급되는 토큰의 `schema_version` 을 올리지도 제한하지도 않는다. |
| `zones` | optional | 구역 선언 (§4.1). |
| `objects` | optional | 물체 선언 (§4.2). |
| `robots` | optional | 로봇 선언 (§4.3). |
| `constraints` | optional | 규칙 선언 (§5). |
| `actions` | optional | 등록된 액션 이름과 그 클래스 (§4.4). |
| `policy` | optional | 현장이 선언하는 이슈어 처분 (§4.5). |
| `custom_events` | optional | 내장 종류에 대응되는 고객 정의 컨텍스트 이벤트 이름 (§4.6). |

모든 절이 선택이고, 없는 절은 **기본값이 채워지는 것이 아니라 없는 것**이다.
`robots` 가 없는 모델도 컴파일되고, 그 뒤 모든 발급 요청은 `AGENT_NOT_IN_MODEL`
로 거부된다 — 이슈어에게 그 요청을 인가할 세계 상태가 없기 때문이다. 의도된
실패의 모양이지만 분명히 적어 둔다: **빈 모델은 관대한 모델이 아니라 엄격한
모델이다.**

## 4. 개체

### 4.1 `zones`

<!-- vocab: zones -->

| 필드 | 필수성 | 뜻 |
| --- | --- | --- |
| `id` | required | 구역 지역 id. 노드 `zone:<id>` 가 된다. 중복은 컴파일 중단. |
| `type` | optional | 자유 문자열. 노드 속성으로 실린다. 컴파일러가 해석하지 않고 어떤 거부도 읽지 않는다 — 규칙이 아니라 스냅숏 안의 증거다. |
| `adjacent` | optional | 인접 구역 id 목록. |

`adjacent` 는 **존재만 검사한다.** 적힌 구역은 선언돼 있어야 하지만 대칭은
요구하지 않는다 — `a: [b]` 만 있고 `b: [a]` 가 없어도 컴파일된다. 인접성은
정렬된 노드 속성(증거)으로 실릴 뿐 경로 간선이 아니므로, 비대칭 선언이 어떤
발급 판단도 오도하지 못한다. 항법 그래프로 읽지 말 것.

### 4.2 `objects`

<!-- vocab: objects -->

| 필드 | 필수성 | 뜻 |
| --- | --- | --- |
| `id` | required | 물체 지역 id. 노드 `object:<id>` 가 된다. 중복은 컴파일 중단. |
| `at` | optional | 물체가 있는 구역. `zone:<at>` 로 가는 `LOCATED_IN` 간선을 낸다. 그 구역은 선언돼 있어야 한다. |

물체의 **위치**는 런타임 컨텍스트 이벤트로 바뀔 수 있다. **존재**는 바뀌지
않는다 — 여기 선언되지 않은 물체는 세계에 없다.

### 4.3 `robots`

<!-- vocab: robots -->

| 필드 | 필수성 | 뜻 |
| --- | --- | --- |
| `id` | required | 로봇 지역 id. 에이전트 노드 `robot:<id>` 와 실행기 노드 `executor:<id>`, 그리고 둘 사이의 `OPERATES` 간선이 생긴다. 중복은 컴파일 중단. |
| `capabilities` | optional | 정렬돼 노드 속성으로 실린다. 증거로 기록될 뿐 어떤 발급 경로도 읽지 않는다 — 능력을 적는다고 무엇이 허가되거나 보류되지 않는다. |
| `schema` | optional | 로봇별 노드 속성. 증거로 기록될 뿐 아무도 읽지 않는다. |
| `home` | optional | 로봇이 있는 구역. `zone:<home>` 로 가는 `LOCATED_IN` 간선을 낸다. 그 구역은 선언돼 있어야 한다. |
| `robot_class` | optional | `spec/SKILL_VOCAB.tsv` 의 로봇 종류 낱말(`diff_drive_amr`·`humanoid` …). 이슈어가 이 로봇의 계획 스텝을 대조할 스킬 등재부(`skills.<robot_class>.yaml`, `spec/SKILLS.md`)를 고른다. 있으면 노드 속성으로 기록되고, 없으면 「등재부 없음」이다 — production 이슈어는 그런 로봇을 서빙하지 않고(S39), dev 이슈어는 legacy 경로로 발급하며 저널에 그렇게 적는다(`skill_matched: false`). |

파서에서 `home` 은 선택이지만, **에이전트를 구역 안에 놓는 것이 바로 이것**이고
**구역 범위 규칙은 구역 안에 있는 에이전트에게만 닿는다.** 요청의 판정 부분그래프는
에이전트에서 바깥으로 만들어진다 — 그 구역, 그 구역의 제약, 그 구역의 사람 순서다.
`home` 이 없는 로봇은 구역이 없으므로 어떤 구역 제약도, 같은 구역의 사람도 끌려
들어오지 않는다. 자기 생애주기 상태로는 여전히 거부될 수 있지만(§6), `"*"` 로 쓴
`human_exclusion` 은 그 로봇을 덮지 않는다.

로봇을 구역 사이로 옮기는 런타임 이벤트는 없다. 로봇의 구역은 적재된 모델이 사는
동안 `home` 이 말한 그대로다.

### 4.4 `actions`

<!-- vocab: actions -->

| 필드 | 필수성 | 뜻 |
| --- | --- | --- |
| `name` | optional | 계획 스텝이 `ActionSpec.name` 에 실을 수 있는 액션 이름. 중복은 컴파일 중단. 파서는 빈 이름을 거부하지 않으며, 빈 이름은 어떤 스텝과도 맞지 않는다. |
| `classes` | optional | `MOVE`·`MANIPULATE`·`ACTUATE`·`NONE` 중 하나 이상. 이 이름을 부르면서 다른 클래스를 적은 스텝은 거부된다(`ERR_ACTION_CLASS_MISMATCH`). 파서는 빈 목록을 거부하지 않는다 — 클래스 없는 항목은 클래스 없는 이름을 등록한다. |
| `description` | optional | 자유 문자열, 기록된다. |

`actions` 등록부는 현장이 아는 이름의 선언이다. 스킬 등재부(`spec/SKILLS.md`)가 아니다:
스킬 등재부는 로봇 종류별이고, 이슈어가 모든 스텝을 대조하는 허용 목록이며, 봉투·피드·안전
상태를 싣는다. `actions` 에 있어도 그 로봇의 스킬 등재부에 없는 이름은 거부된다(`skill not registered`).

### 4.6 `custom_events`

<!-- vocab: custom_events -->

| 필드 | | 뜻 |
| --- | --- | --- |
| `id` | required | `ContextEvent{kind: CUSTOM}` 가 `custom_kind` 에 싣는 이벤트 이름: `<namespace>.<name>`, 양쪽 모두 소문자 `[a-z0-9_]` 1–32자. 중복은 컴파일 중단. |
| `effect` | required | 이 이름이 적용되는 내장 종류: `HUMAN_ENTER`·`HUMAN_LEAVE`·`OBJECT_MOVE`·`MAINTENANCE_ON`·`MAINTENANCE_OFF`·`CORDON_ON`·`CORDON_OFF` 중 하나. 다른 값은 컴파일 중단. `node_id`/`arg` 는 그 효과의 규약을 따른다(`spec/API_SURFACES.md` §5.1). |
| `description` | optional | 자유 문자열, 기록된다. |

고객 정의 이벤트는 그래프 변경 어휘를 늘리지 않고 하나에 이름을 붙인다. 저널은
효과(`GRAPH_MUTATION.mutation_kind`, 그래서 재생은 그대로)와 선언된 이름(`custom_kind`)을
둘 다 남긴다. 이 절이 선언하지 않은 `custom_kind` 를 가진 `CUSTOM` 이벤트는 거부되며,
추측으로 대응되지 않는다.

| 필드 | 필수성 | 뜻 |
| --- | --- | --- |
| `unverified_targets` | optional | `refuse`(기본) — `target_object_id` 가 선언된 객체가 아닌 스텝은 거부(`ERR_TARGET_UNKNOWN`); `allow` — `TOKEN_ISSUED` 기록에 `target_unverified: true` 를 달고 발급. |

## 5. 제약

제약 type 하나는 레지스트리의 한 항목이다 — 자기 선언을 제약 노드와 `CONSTRAINS`
간선으로 컴파일하는 함수다. 규칙 어휘를 늘리는 일이 여기저기 흩어진 수정이 아니라
**덧붙이는 등록**이 되고, 증거 계약은 움직이지 않는다: 제약은 언제나 속성을 가진
노드이고 같은 정규 인코더가 부호화한다.

모르는 제약 type 은 조용한 건너뜀이 아니라 **컴파일 오류**다. 컴파일할 수 없는
규칙을 승인할 수는 없다 — 오타 난 규칙은 조용히 사라지는 대신 발급을 멈춰야 한다.

각 선언은 `type` 키를 가진 매핑이다. 나머지 키는 그 type 의 화이트리스트로
검사되고, 예상 밖 필드는 버려지는 대신 컴파일을 중단시킨다.

### 5.1 등록된 type

<!-- ctypes -->

| type | 하는 일 |
| --- | --- |
| `human_exclusion` | 구역의 사람 배제 규칙을 제약 노드로 기록한다 (§5.2). |
| `speed_limit` | 2026-09-09 부터 **거부** (§5.3) — 구역별 한도는 `policy.yaml` `guardrails.zones` 에 산다. |
| `exclusive` | 물체를 배타 점유 대상으로 표시한다 (§5.4). |

`zone`·`object` 필드는 `"*"` 를 받으며 각각 선언된 모든 구역·물체로 전개된다.
전개는 **컴파일 시점의 선언**을 기준으로 일어나므로, 나중에 추가된 구역은 이전의
`"*"` 에 덮이지 않는다 — 모델을 다시 컴파일해야 하고, 모델은 기동 시 컴파일되므로
그것은 곧 재기동이다.

### 5.2 `human_exclusion`

<!-- vocab: constraint/human_exclusion -->

| 필드 | 필수성 | 뜻 |
| --- | --- | --- |
| `zone` | required | 구역 id, 또는 선언된 모든 구역을 뜻하는 `"*"`. |

대상 구역마다 제약 노드 하나와 그리로 가는 `CONSTRAINS` 간선을 낸다.

효과를 정확히 읽어야 한다. 이름이 시사하는 것과 다르다. **사람이 에이전트와 같은
구역에 있을 때의 거부는 구조적이다** — 판정기는 에이전트가 속한 구역에 `HUMAN`
노드가 있는지를 볼 뿐 **제약 노드를 참조하지 않는다.** 따라서 `human_exclusion` 을
선언한다고 그 거부가 켜지지 않고, 빼먹는다고 꺼지지 않는다. 선언이 하는 일은
규칙을 스냅숏에 **증거로** 남기는 것이다 — 토큰이 발급된 구역에 대해 현장이 어떤
규칙을 선언했는지가 기록된다.

### 5.3 `speed_limit`

<!-- vocab: constraint/speed_limit -->

| 필드 | 필수성 | 뜻 |
| --- | --- | --- |
| `zone` | required | 구역 id, 또는 선언된 모든 구역을 뜻하는 `"*"`. |
| `max_linear_speed_mps` | optional | 선속도 상한 (m/s). |
| `max_angular_speed_rps` | optional | 각속도 상한 (rad/s). |

**이 제약은 2026-09-09 부터 거부된다(컴파일 오류).** 그때까지 컴파일러는 이것을
아무도 읽지 않는 제약 노드로 기록했다: 게이트는 지령 속도를 *토큰의* 한도와 대조하고,
그 한도는 `policy.yaml` `motion:` 에서만 왔다 — 구역 한도를 「설정한」 현장 모델은
아무것도 설정하지 않았고, 이 페이지는 게이트가 집행한다고 적고 있었다. 정직한
수정은 노드를 배선하는 것이 아니라 한도를 이슈어가 이미 읽는 한 자리로 옮기는 것이었다:

```yaml
# policy.yaml (이슈어)
guardrails:
  common:            # GUARDRAILS.tsv 이름표별 절대 상한
    sls.linear_mps: 1.0
    sls.angular_rps: 1.0
    step.max_duration_s: 30
  zones:             # `common` 을 조이기만 한다(S34)
    z7:
      sls.linear_mps: 0.5
```

이슈어는 발급 시 대상 객체의 구역(`objects[].at`)을 풀어 `min(common, zone)` 을
토큰 제약에 굽고, 게이트가 실제 명령과 대조해 집행한다. 위 필드 표는 옛 파일을
이름으로 진단하기 위해 남긴다; `speed_limit` 을 아직 가진 모델은 적재되지 않는다.

**그 한도를 넘는 요청은 줄여서 발급하지 않고 거부한다.** 이슈어는 계획 스텝이 요청한
값 — twist 의 선·각속도 크기(후진·대각도 같은 한도), `duration_sec`, 봉투 이름표와 같은
이름의 `params_json` 숫자 값 — 을 `min(common, zone)` 과 대조한다. 하나라도 넘거나
유한한 수가 아니면 계획은 `ERR_ENVELOPE_EXCEEDED` 로 거부되고 토큰은 발급되지 않는다.
`Denial.exceeded` 는 넘은 한도마다 `{name, requested, max}` 한 줄을 실어, 클라이언트가
사용자에게 어느 한도에 걸렸는지 알려 줄 수 있게 한다(단위: `GUARDRAILS.tsv`). 이슈어는
요청을 더 짧거나 느린 형태로 바꿔 발급하지 않는다 — 요청자가 계획하지 않은 부분 실행은
명령을 고치는 일이고, PAIL 은 명령을 고치지 않는다. 한도 안의 요청은 속도에는 한도를,
시간에는 요청한 값을 실은 토큰을 받는다.

### 5.4 `exclusive`

<!-- vocab: constraint/exclusive -->

| 필드 | 필수성 | 뜻 |
| --- | --- | --- |
| `object` | required | 물체 id, 또는 선언된 모든 물체를 뜻하는 `"*"`. |

물체 노드에 `exclusive` 속성을 세운다 — 제약 노드는 만들지 않는다. 이것은 앞으로를
위한 고리다. 발급은 **점유를 판정하지 않는다.** 오늘 물체를 배타로 표시하는 것은
스냅숏에 의도를 기록할 뿐 아무것도 거부하지 않는다. 상호 배제 수단으로 배치하지
말 것.

## 6. 컴파일된 모델이 거부할 수 있는 것

사이트 모델이 발급을 좌우하는 길은 정확히 넷이다. 그 밖에 선언하는 것은 전부
증거다.

| 거부 | 언제 |
| --- | --- |
| 컴파일 중단 | 파일을 읽지 못하거나 유효하지 않다. 이슈어는 기동하고 모든 발급을 거부한다 (§2). |
| `AGENT_NOT_IN_MODEL` | 모델이 선언한 적 없는 로봇을 요청이 지목한다. |
| `NODE_MAINTENANCE` / `NODE_CORDONED` | 에이전트 노드가 그 생애주기 상태다(이 파일이 아니라 런타임에 설정된다). |
| `HUMAN_IN_ZONE` | 에이전트가 속한 구역에 사람이 있다 (§5.2). |

위의 표들을 읽을 때 이 구분이 중요하다. `type`·`capabilities`·`schema`·
`adjacent` 는 기록되고 해시되므로 사후 감사가 가능하지만, 이슈어의 어떤 분기도
그것들을 보지 않는다. **그 칸을 채운다고 모델이 더 안전해지지 않는다.**

## 7. 완전한 모델 한 벌

실린 예제 `config/site_model.example.yaml` 은 그대로 컴파일된다. 정본 §7 이 그
파일의 머리와 제약 절을 바이트 그대로 인용한다.

## 8. 이 문서를 정직하게 유지하는 방법

위의 모든 것은 주장이 아니라 실측이다. `spec/tools/spec_site_model_check.py` 가
컴파일러 소스와 실린 예제를 읽어 세 어휘를 대조한다.

```
이 문서  ==  컴파일러 소스  ==  실린 예제
```

둘만으로는 부족하다. 문서와 예제만 재면 파서가 받아들인 적 없는 철자를 둘이
합의할 수 있고, 문서와 파서만 재면 예제가 조용히 낡아 독자가 가장 먼저 돌려보는
것이 깨진다. 인용 블록은 전부 그것이 가리키는 파일의 **바이트 부분문자열**로
검사되고, 이 문서가 가리키는 모든 파일은 실제로 실리는지 검사된다 — 받은 사람이
자기 손에 있는 것으로 대조할 수 없는 인용은 인용이 아니라 주장이다.
