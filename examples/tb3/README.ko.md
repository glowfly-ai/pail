# TurtleBot3 기준 예제 — 구동 명령 앞의 인가 (한국어 안내)
<!-- ko-structure: abridged -->

> 이 한국어판은 영문판보다 절·표·코드 블록이 적은 요약본이다. 영문판이 정본이며, 두 판이 다르면 영문판이 우선한다.

> **0.2 평가 묶음:** 먼저 평가 디렉터리에서 `python3 evaluation.py load`를 실행합니다.
> 이슈어는 평가 이미지로 실행합니다. 아래의 저수준 명령은 그 뒤 `pail-core/`에서 사용합니다.
> 처음에는 `evaluation.py` 실행 도구를 권합니다.


영어 원문 [README.md](README.md)가 정본이며, 이 문서는 설치·실행·데모 절차를 한국어로 옮긴 것이다.
두 문서가 다르면 영어 원문을 따른다.

이 예제에는 실제 PAIL 게이트와 모션 브리지, 합성 신원·안전 입력, 그리고 **베이스 명령 싱크**가
들어 있다. 싱크는 `/drive_cmd_vel`을 읽기만 하고 바퀴 움직임을 흉내 내지 않는다. 모터, 시리얼
장치, 호스트 네트워크, 외부 서비스 계정은 쓰지 않는다. 소프트웨어 경로는 다음과 같다.

`플래너 /cmd_vel → PAIL 게이트 /safe_cmd_vel → 모션 브리지 /drive_cmd_vel → 베이스 싱크`

## 로봇 없이 실행하기

준비물: Docker Engine/Desktop(compose 플러그인 v2 이상), Python 3, OpenSSL. 리눅스 컨테이너 엔진에 메모리
4 GB 이상을 준다. ARM64와 x86-64 소스 빌드를 Dockerfile이 지원하지만, 한 번의 성공은 그 실행의
증거에 기록된 플랫폼에 대해서만 성립한다. 다운로드를 포함한 첫 빌드는 10~20분 이상 걸릴 수 있고,
캐시가 있으면 몇 분으로 줄어든다. 운영체제별 제한과 결과 해석은 [설치와 결과](../../TRY_IT.ko.md)를 본다.

이 저장소의 루트에서:

```sh
python3 examples/tb3/run.py
```

러너는 **이 소스 트리**를 빌드하고, 새 로컬 키를 만들고, mTLS와 SROS2 신원을 준비하고, 별도의
루트 키로 키링에 서명한 뒤, 사설 Docker 네트워크를 띄운다. 루트 서명 키는 실행 중인 서비스에
마운트되지 않는다. 생성된 키와 상태는 화면에 찍히는 `STATE=...` 디렉터리에 두며, 이 디렉터리는
**소스 트리 밖**이다. 소스 트리는 바뀌지 않는다. 그 상태 디렉터리 전체를 공유하지 말 것 — 개인
키가 들어 있다. 대신 `evidence/` 디렉터리를 검토한 사본으로 공유한다.

예제는 v5 토큰과 `robot_class=diff_drive_amr`를 고른다. 확인하는 것:

- 게이트가 스킬 등재부를 읽는다;
- 인가가 없으면 베이스 싱크에 0이 아닌 명령이 오지 않는다;
- 실제 v5 토큰이 `twist`, 슬롯, 서명된 제약을 담는다;
- 같은 베이스 관측자가 맞는 토큰 아래서 움직임을 받는다;
- 시간이 다 되면 전달이 멈춘다;
- 한도 0.1 m/s 아래서 0.2 m/s 요청은 거부된다;
- 게이트를 죽이면 플래너가 계속 보내도 브리지가 0을 낸다;
- 생성된 저널이 이슈어 공개키로 검증된다.

소프트웨어는 명시적으로 선언된 **개발 프로파일**로 돌며, mTLS·SROS2 Enforce·루트 서명 키링을
쓴다. 합성 RFID 증거는 실제 센서가 아니고, 합성 안전 피드는 안전 컨트롤러가 아니다. 선언되지 않은
물리적 안전 컨트롤러와 그 밖의 한계는 그대로 남는다 — 이것은 안전 인증이 아니다.

## 라이브 데모 콘솔 (하드웨어 없이)

화면 캡처와 장면별 설명이 있는 따라 하기 안내: [`DEMO.ko.md`](DEMO.ko.md)(영어 원문
[`DEMO.md`](DEMO.md)). 이 절은 참조용 요약이다.

`run.py`는 경로를 검사하고 끝난다. `demo.py`는 같은 스택 — 실제 이슈어, 실제 게이트, 실제 모션
브리지, 새로 만든 키 — 을 계속 띄운 채 **시뮬레이션** 베이스를 붙이고, 이 컴퓨터에서만 보이는
콘솔을 `http://127.0.0.1:8765/`에 연다.

```sh
python3 examples/tb3/demo.py build --build-window-confirmed
python3 examples/tb3/demo.py start
python3 examples/tb3/demo_scenes.py        # 선택: 아래 장면을 전부 돌리고 판정한다
```

`forward 1 m`, `back 0.5 m`, `left 90 deg`, `left 1 m`, `forward 1 m at 0.3 m/s` 같은 명령을
입력한다(한국어도 된다: `앞으로 1m`, `뒤로 50cm`, `왼쪽으로 90도`, `정지`). 콘솔이 이것을
트위스트 계획으로 바꿔 이슈어에 요청한다. 데모 정책은 0.1 m/s, 0.5 rad/s, 1회 15 s를 허용하므로
한 번의 호출로 최대 1.5 m를 간다.

| 장면 | 기대 |
|---|---|
| 앞으로 1 m | 발급 → 시뮬레이션 베이스가 약 1 m 이동 → 정지 |
| 앞으로 3 m / 0.3 m/s로 1 m | **이슈어가 거부**(`ERR_ENVELOPE_EXCEEDED`); 아무것도 움직이지 않음; 콘솔이 넘은 한도를 이름으로 알려 줌 |
| 왼쪽 90도 / 뒤로 0.5 m / 왼쪽으로 1 m | 제자리 회전 / 후진 / 90° 회전 뒤 1 m(토큰 두 장) |
| 허가 뒤 플래너가 0.3 m/s로 가속 | 게이트가 모든 명령을 거부(`ERR_CONSTRAINT`); 허가 안으로 돌아오면 재개 |
| 계획 없이 구동 | 게이트 거부(`ERR_NO_TOKEN`) |
| 다른 태그 판독 | 맞는 태그를 읽을 때까지 게이트 거부(`ERR_TARGET_MISMATCH`) |
| 주행 중 안전 UNSAFE | 정지; 끊긴 계획은 재개되지 않음(`CHAIN_REVOKED`); 안전이 OK면 새 계획이 발급됨 — 운영자 잠금(`SAFE_STOP`)은 위조 토큰 보고용이지 안전 사건용이 아님 |
| 주행 중 정지 | 플래너는 멈추고 콘솔이 이슈어에서 계획을 취소(`CancelPlan`, 원장 `CHAIN_CANCELLED`); 다음 계획은 자기 토큰으로만 돌고, 취소된 계획의 남은 창으로는 절대 돌지 않음 |
| 원장 검증 | 서명된 저널이 검증됨 |

계획이 끝나면 콘솔은 베이스가 정지한 뒤 관측한 변위를 기록한다(`moved` 이벤트). 화면은 그 기록을
보여 주며, 실시간이든 새로고침 뒤든 같은 값이다.

이슈어는 한도를 넘는 요청을 더 짧거나 느린 버전으로 바꿔 발급하지 않는다 — 거부하고, 넘은
한도를 하나씩 돌려준다(`Denial.exceeded`). `demo_scenes.py`는 「아무것도 안 움직였다」를 침묵만으로
판정하지 않는다: 모든 거부 뒤에는 같은 관측자가 보아야 하는 허가된 이동이 따른다. Ctrl-C(또는
SIGTERM)로 스택을 내린다.

이 예제가 아닌 것: 위치는 게이트를 통과한 명령의 시뮬레이션이지 바퀴 엔코더가 아니다; 태그와 안전
입력은 합성 피드다. 콘솔은 로컬 시연용 요청자이지 운영 대시보드가 아니다.

로봇 쪽 시계가 튀면(macOS용 Docker Desktop에서 +1.96 s 한 번 관측됨) 게이트는 재시작할 때까지
모든 명령을 `ERR_CLOCK_DRIFT`로 거부한다 — 튄 시계를 다시 기준 잡지 않는 것이 설계다. 콘솔은 튐을
알리고 「로봇 쪽 재시작」을 제공하며, `demo_scenes.py`는 장면을 탓하는 대신
`CLOCK_PREREQUISITE_FAILED`를 보고한다. 드리프트 한도는 완화하지 않는다.

## 초록 줄이 아니라 증거

화면에 찍히는 증거 경로에 `FINAL_RESULT.json`, 검사별 기대/실측 값과 시각, `runtime/*.jsonl`,
서비스 로그, 저널 파일, 소스 매니페스트, `MANIFEST.json`이 있다. 관측자가 없으면 차단 성공을
세울 수 없다: 같은 관측자가 이어서 인가된 트래픽을 받아야 한다. 실패한 실행도 디스크에 남는다.
러너는 실패 시에도 자기 Compose 프로젝트만 내린다.

`--state /절대경로/새/디렉터리`로 비어 있는 새 목적지를 고른다. 기존 실행은 지우지 않는다.
`--skip-build`는 `PAIL_TB3_CLOUD_IMAGE`와 `PAIL_TB3_GATE_IMAGE`를 명시해야 하며, 그런 실행을
새 소스 빌드라고 부르지 말 것.

## 실제 TurtleBot3 베이스 연결 — 별도의 통합 단계

실행 가능한 절차 — 로봇 쪽 리그, 운영자 쪽 이슈어와 콘솔, 설정 분리, 배치 진술, 장면, 관리자의
실측 결과 — 는 [`HARDWARE.ko.md`](HARDWARE.ko.md)에 있고 파일은 [`hardware/`](hardware/)에
있다. 이 절은 그 절차가 따르는 통합 규칙을 적는다.

벤더의 ROS 2 Humble TurtleBot3 베이스 드라이버와 펌웨어를 쓴다; 여기에 포함하거나 고치지 않았다.
<https://emanual.robotis.com/docs/en/platform/turtlebot3/bringup/> 참고. OpenMANIPULATOR 팔과
독점 인식 드라이버는 이 기준 예제 밖이다.

하드웨어 배치에는 **별도로 검토한** 로봇 쪽 설정을 만든다. 이 올인원 개발 설정을 로봇에 복사하지
말 것: 이슈어·운영자 개인 키는 이슈어·운영자 호스트에 둔다. 로봇에는 필요한 신원과 신뢰 검증
재료만 준다. 베이스 드라이버에는 `/driver` SROS2 엔클레이브를 쓰고, 명령 구독을 `/cmd_vel`에서
`/drive_cmd_vel`로 리맵한다. 다른 명령 경로는 제거하거나 금지한다; 접근 통제 없는 리맵은 우회
방벽이 아니다. 그 배치에 맞는 정책, 서명된 키링, mTLS 엔드포인트, 스킬 등재부로 PAIL 게이트와
브리지를 시작한다.

`fastdds_loopback.xml` 샘플은 **오직** 이 예제의 공유 사설 네임스페이스용이다. 물리적 다중 호스트
배치는 자체 검토한 DDS 네트워킹이 필요하다. 인가된 진단 참가자에서
`ros2 topic info /drive_cmd_vel --verbose`로 실제 구독을 확인하고, 통제된 환경에서 바퀴·엔코더
움직임과 정지 동작을 따로 시험한다. 베이스 싱크 시험 통과는 물리적 바퀴 증거가 아니다. 로봇의
하드웨어 안전과 비상정지는 독립된 책임으로 남는다.

### 선택: 베이스 드라이버만 띄우는 launch

`tb3_base_driver.launch.py`는 기본값으로 하드웨어를 시작하지 않는다. `enable_hardware:=true`를
명시하고, SROS2 Enforce가 켜져 있고, 모델 파라미터 파일과 로봇 키스토어가 있을 때만 벤더의
`turtlebot3_ros` 실행 파일을 쓴다. 명령 입력을 `/drive_cmd_vel`로 리맵하고 `/driver`를 고르며,
PAIL 브리지에 맞춰 스탬프 없는 `Twist` 입력을 요청한다. 설치된 드라이버 버전에서 메시지 타입과
구독을 확인할 것; 이 코드는 물리 검증이 아니다.

준비된 로봇에서(장치 없는 개발용 Compose 스택 안이 아님):

```sh
# 기본값은 무해한 설정 검사: 드라이버를 시작하지 않는다.
ros2 launch examples/tb3/tb3_base_driver.launch.py
# 하드웨어·펌웨어·보안·명령 경로·안전 검토 뒤에만:
ros2 launch examples/tb3/tb3_base_driver.launch.py enable_hardware:=true \
  params_file:=/absolute/path/to/vendor/model.yaml usb_port:=/dev/ttyACM0
```

보호되지 않은 `/cmd_vel`을 함께 소비하는 두 번째 벤더 bringup을 띄우지 말 것. 이 선택 launch는
라이다, 팔, 인식 시스템, 안전 컨트롤러를 시작하지 않는다.

### 하드웨어 관측과 남은 한계

유지보수자의 별도 픽스처가 2026-09-14와 2026-09-15에 공식 Humble TurtleBot3 waffle_pi 드라이버,
실제 OpenCR, 두 바퀴 엔코더로 위 데모 장면 전부를 바퀴를 띄운 채, 그리고 직선 왕복·제자리
회전·주행 중 정지·주행 중 UNSAFE 장면을 바닥 1.5 m 공간에서 관측했다. 신원·안전 입력은
합성이었다. 그 과정에서 소프트웨어 결함 셋을 고쳤다: 게이트웨이가 첫 응답을 기한 안에 받지
못해 영구 NO_TOKEN이 되던 것, 완료 보고를 앞지른 응답이 소비된 스텝을 되살리던 것, 그리고
이슈어에서 취소한 계획을 위임 창을 쥔 게이트웨이가 스텝 창이 끝날 때까지 계속 달리던 것(취소가
이제 `CHAIN_REVOKED` 비콘으로 엣지에 닿는다). 이것은 변경 없는 소스 ZIP 설치 시험이 아니었고,
이 기본 싱크 예제를 하드웨어 시험으로 바꾸지 않으며, 바닥 제동 성능을 인증하지 않는다.

RPi 시계 조정 중 `ERR_CLOCK_DRIFT`가 2026-09-14에 한 번 관측됐고 그 뒤 재현되지 않았다. 시계
검사를 끄거나, 인가 한도를 늘리거나, 이슈어 저널을 초기화해 그런 거부를 통과로 바꾸지 말 것.
정확한 오류와 시계를 기록하고, 평가 피드백에서는 전제 조건 실패와 기능 판정을 구분한다.

## 이미지 보존

실행별 이미지 태그는 기본으로 남기며 정확한 제거 명령을 찍어 준다. `--remove-images`는 이미지
ID와 증거를 남긴 뒤 이 호출이 빌드한 태그만 지운다. `--skip-build`에서는 넘겨준 이미지를 항상
보존한다. `evidence/image-cleanup.json`을 본다; 정리 실패는 인가 판정을 바꾸지 않는다.

## 공개 참조 파일 권한

러너는 launch 파일, 모의 액터, Fast DDS XML, 접근 검사기를 이 실행의 `runtime/reference/`에
복사한다(디렉터리 0755, 파일 0644). 스택을 띄우기 전에 정확한 바이트를 컨테이너 UID 10001로
읽을 수 있는지 확인한다. 체크아웃에는 chmod나 chown을 하지 않는다. `evidence/reference-files.json`과
`reference-access.log`에 사본 해시와 런타임 읽기 프로브를 기록한다. 이 권한 규칙은 이 공개
입력에만 적용되며, 생성된 개인 키(0600)에는 절대 적용하지 않는다.

## UID 간 접근 계약

`permissions.py`가 상태 디렉터리 모드와 소유권 역할의 실행 가능한 정본이다.
`python3 examples/tb3/permissions.py describe`가 선언된 계약을 찍는다. 러너는 생성 시와 소유권
이전 뒤에 이를 적용하고, 액터를 띄우기 전에 서비스(UID 10001)와 실제 호스트 실행자 양쪽으로
접근을 검사한다. `evidence/access-contract.json`에 결과를 기록한다. chmod 호출만으로는 증명이
아니다. 나중의 읽기 실패, 로그 소실·축소는 전제 조건 실패이지 빈 관측 창의 성공이 아니다.

- 공유 합성 관측: `evidence/runtime`은 0755; JSONL과 프로세스 로그는 생산자의 umask가 077이어도
  명시적으로 0644.
- 사설 설정 루트, 키링 상태, 루트 키 디렉터리는 제한된 채 유지. 개인 키 파일은 0600을 유지하며
  호스트 읽기를 위해 넓히지 않는다.
- 참조·제어는 공개 시험 입력이며, 그 읽기 가능한 모드는 키에 적용되지 않는다.
- 생성된 SROS2 링크는 준비 중 생성된 설정 트리 안만 가리킬 수 있다.

새 상태를 `umask 022`와 `umask 077` 양쪽에서 돌린다. 소스 모드 정규화는 리눅스 unzip으로 실제
푼 ZIP을 시험하는 것을 대신하지 못한다.

## 완료와 시계 전제 조건

완료 검사는 발급된 토큰의 `step complete: token ... consumed` 표시와 그에 맞는 consumed/no-token
BLOCK을 요구하며, 아무 일시적 BLOCK으로 대신하지 않는다. 관측 행은 벽시계와 단조 시각을 함께
담는다. 관측 중 0.25초를 넘는 벽시계/단조 불연속이나 `ERR_CLOCK_DRIFT` 관측은
`clock-prerequisite.json`을 남기고 실행을 전제 조건 실패(exit 2)로 끝낸다. 이것은 하네스 안정성
검사이지 PAIL 보안 임계값의 변경이나 시계 오류의 유일한 원인 증명이 아니다. 다시 돌리기 전에
VM/호스트 시계 소스를 살핀다; 러너는 시계나 동기화 서비스를 바꾸지 않는다. 실패와 원시 로그는
증거로 남으며, 물리 제동 측정이 아니다.

### 명령 전송 신선도

게이트→브리지와 브리지→드라이버의 속도 발행은 RELIABLE·volatile·깊이 1의
DDS 이력과 허가 deadline(기본 100 ms)에 해당하는 샘플 수명을 사용합니다.
허가 신호도 같은 시간 범위에서 만료됩니다. 이는 오래된 DDS 명령의 전달을
제한하는 것이며, 모터 제어 루프의 지연이나 물리적 정지거리를 측정한 값이 아닙니다.
통합자는 드라이버 자체의 명령 watchdog을 유지하고 RMW·드라이버 조합을 검증해야
합니다. 드라이버가 이미 수락한 명령에는 DDS 샘플 수명이 적용되지 않습니다.
