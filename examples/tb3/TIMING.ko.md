# TB3 시간 예산과 복구 프로필
<!-- ko-structure: abridged -->

> 이 한국어판은 영문판보다 절·표·코드 블록이 적은 요약본이다. 영문판이 정본이며, 두 판이 다르면 영문판이 우선한다.

정본: [TIMING.md](TIMING.md). 소프트웨어 통합 프로필이며 물리적 제동 보장이 아니다.

## 판정·완료·물리 결과를 구분

원래 허용/차단 판정을 보존한다. `GateState.completed_token_id`는 로컬 소비이며
Issuer의 완료 수락이나 물리 작업 성공의 증거가 아니다. `step_deadline_elapsed_ms`와
`step_clock_id`는 실제 허가 창의 관측 정보일 뿐 새 인가가 아니다. 관련 ROS 노드는
같은 메시지 정의로 재빌드한다.

## 현재 예제 예산

| 요소 | 값 |
|---|---|
| 계획기 발행/종료 검사 | 100ms |
| 명령 전달 예산 | 100ms |
| 스케줄 여유 | 50ms |
| 비영속도 발행 종료 | 게이트의 실제 경과시간 기한 250ms 전 |
| 0 명령 | 전달 예산이 남았을 때만 발행. 만료 뒤 꼬리 명령 없음 |
| 허가 heartbeat | 20Hz, 공칭 50ms |
| DDS deadline / 브리지 watchdog | 100/200ms. 전달 직전에도 나이 검사 |
| 재검사 / 로컬 agent RPC | 100/50ms. RPC 뒤 정상 완료를 처리 |
| agent mirror / grace | 200ms 설정 / 연속 재검사 3회. 전체 물리 정지 상한과 다름 |
| 시계 편차 | 시작 wall/steady 기준 대비 500ms. UTC 정확성 인증이 아님 |

콘솔은 토큰 발급 전에 스텝마다 **0.35초의 인가 예비시간**(기동 관측 0.10 + 종료 0.25)을
Issuer에 명시적으로 요청한다. 원래 운동 지속시간은 별도로 계획기에 전달한다.
새 토큰의 요청 인가시간은 순수 운동시간보다 커지지만, 기존 토큰의 기한을 연장하거나
정책의 최대 시간·속도를 늘리지 않는다. 운동+예비시간이 정책에 안 맞으면 Issuer가 거부하며
화면의 1회 운동 최대값도 그에 맞게 줄인다. 계획기는 운동 목표시간과 실제 게이트 기한 중
먼저 도달한 쪽에서 끝낸다. 더 좁은 새 계획의 기한이 항상 우선한다.

처음에는 0 명령으로 허가 창을 관측한다. 게이트와 같은 Linux 부팅/BOOTTIME namespace를
확인한 경우에만 실제 기한을 쓴다. 같은 토큰의 기한을 연장하지 않고, 다음 스텝은
이전 토큰의 실제 로컬 소비를 기다린다. 시계가 없거나 다르면 비영속도 명령을 보내지
않는다. 새 계획의 허가가 기존 스트림의 기한을 줄일 수 있다. 최종 판정은 항상 게이트다.

이 상수들은 참조 프로필이지 모든 환경의 최악 지연 실측값이 아니다. 포팅 시 부하별
꼬리 지연·거리·회전을 함께 측정한다. 조기 종료는 시간 기반 이동 거리를 줄일 수 있다.
그 차이를 제한 밖 속도나 묵시적인 허가 창 확대로 보상하지 않는다. 다른 프로필은
명시적인 버전 변경·시험으로 적용하며, 예제 상수를 서명된 원격 런타임 정책처럼 주장하지 않는다.

## 기록·반복·운영

명령/토큰, 원래 사유, command/recheck/step_timer 경로, 기한·초과·시계 원인과 실제
설정을 남긴다. 경보 표시는 묶어도 모든 HOLD 시간·다운타임·재시도를 지표에 포함한다.
작은 초과를 자동으로 성공 완료로 처리하지 않는다. 늦은 명령·과속·대상 불일치·잘못된
인가의 음성 대조를 유지한다. 13/13 한 번으로 실패율 0을 주장하지 않는다. 냉기동·안정
운전·정해진 부하·복구를 구분하고 사전에 정한 반복을 모두 보존한다.

## 시계 복구

벽시계 편차는 매번 비교하는 조건이다. 기존 관계가 범위 안으로 돌아오면 그 조건은
풀릴 수 있으나 기존 토큰·스텝·안전·증거 조건은 여전히 필요하다. 경과시계 실패·역행은
별도 세션 래치다. 어느 경우에도 예산을 초기화하지 않는다.

실물 참조 계획기는 `ERR_CLOCK_DRIFT`에서 남은 스텝을 포함해 지시 전체를 중단한다.
기존 사설 런타임 마운트의 `/state/demo_planner_clock_abort.json`에 중단 토큰을 기록한다.
시계 복귀·피드/속도 변경·계획기 재시작만으로 기록이 풀리지 않는다. 옛 토큰과
겹치지 않는 새 계획 토큰을 게이트가 실제 허가해야 풀리며 그 전에는 0 명령만 탐색한다.
지시 번호는 콘솔 재시작으로 재사용될 수 있어 계획의 신원이 아니다. raw 요청은 풀지 못한다. 저장소 읽기·쓰기
오류는 참조 동작을 막는다. 저장소와 옛 권한을 확인하고 stop/cancel로 정리한다. 쓰기 실패
뒤 재시작했다고 중단 기록이 영속화됐다고 볼 수 없으며, 우회하려고 파일을 삭제하지 않는다.
시계 중단을 `plan_done` 성공으로 기록하지 않는다. 이는 참조 계획기 정책이지 게이트의
새 세대 차단은 아니다. 다른 클라이언트는 여전히 기존 토큰/스텝 조건의 적용을 받는다.

이번 판은 자동 재기준·자동 재시작을 추가하지 않는다. 권고 절차는
HOLD/증거 보존 → 시각 신뢰·불확실성 확인 → 키·영속 하한 확인 → Issuer/agent의 체인·리스·
소비 재조정과 옛 권한 정리 → 준비 상태 → 기계/작업 조건이 허용할 때 새 계획 제출이다.
거부를 피하려고 상태 파일을 지우지 않는다. 시간 소스 충돌을 막고 가동 중 큰 step을
피한다. 재시작만으로 신뢰를 증명하지 않는다. 이것은 운영 지침이며 새 자동 복구
프로토콜이 아니다. 인증된 시간·구세대 권한 차단·자동 재개는 별도 설계가 필요하다.
유효한 위임 리스의 오프라인 동작과 무인가 동작을 혼동하지 않는다. 절전·slew는 실제 OS에서 시험한다.

## 반복 시계 WARN

사람이 읽는 `ERR_CLOCK_DRIFT` WARN만 모은다. command/recheck/step_timer 경로마다
첫 오류·원인 변경은 즉시, 반복은 steady_clock 기준 초당 최대 한 줄로 요약한다.
숫자 편차가 변해도 간격을 초기화하지 않는다. interval_count는 앞 줄 이후 새 거부 수,
total_count는 해당 경로·원인 구간의 누적 수다. event=end가 남은 수를 내보낸다.
이는 경고 스트림 종료이지 UTC 신뢰·동작 준비의 증명이 아니다. 프로세스가 종료되면
마지막 부분 구간이 출력되지 않을 수 있으므로 WARN은 무손실 판정 원장이 아니다.
GateState와 기존 판정 보고는 원래 주기·사유·수치 그대로 유지한다. HOLD/중단시간은
WARN 줄 수가 아니라 판정 관측에서 계산한다. 경로마다 한 줄이므로 전체 경로를 합쳐
초당 한 줄이라는 의미는 아니다.

## 키링 상한

`PAIL_HW_KEYRING_MAX_LIFETIME_SEC`는 게이트의 남은 번들 유효기간 상한이다.
적재 시 `expires_at−now`를 검사하며 번들의 나이가 아니다. C++ 기본값은 호환성을 위한
86400초이고 명시 값은 Go duration 표현 범위의 양의 십진 정수여야 한다. Go는 별도 명시
설정을 요구한다. 각 구성요소의 값을 명시하고 같다고 추정하지 않는다. 잘못된 값이나
초과 시 기동을 거부하며, 1초 상한은 8시간 번들을 거부하고 버전 상태를 전진시키지 않는다.
서명·rollback·절대 만료 검사는 별도로 유지한다.
